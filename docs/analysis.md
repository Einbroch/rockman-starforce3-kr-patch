## 대사 형식

- 파일 = 8바이트 항목(위치, 크기) 표 + 블록. 끝 항목은 `(파일 크기, 0)`(2편은 `0xFFFF`).
- 크기 최상위 비트 = 압축, **압축은 LZ11**(머리 `0x11`, 2편은 LZ10). `mess_sub` 86블록 중 74개가 압축. `tools/lz11.py`.
- 블록 = 3편 GSM 아카이브: `" GSM"` + `00 01` + 스크립트 수 u16 + (최대 크기/2−1) u16 + `FF FF`,
  스크립트 항목(u16 위치, u16 크기/2−1), 스크립트 본문은 **0x55 로 XOR**.
- TextPet(Prof9, 커밋 6c6d705) 에 3편 전용 리더·라이터(`-f gsm`)와 `mmsf3.ini`·`rnr3-utf8.tbl`·`sf3-utf8.tbl` 이 이미 있다.
  `python tools/script.py check work/jp_rj rnr3` → **일본판 729블록, 영어판 723블록 전부 원본과 바이트까지 같게 왕복**.
- 다시 묶을 때 안 바꾼 블록은 원본 저장 바이트를 그대로 쓴다(`script.write_mess(blocks, originals)`). LZ11 재압축은 원본과 바이트가 다르다.

## 문자 코드 — 3편은 UTF-16

**3편 대사는 유니코드(UTF-16LE)다.** 문자표 `rnr3-utf8.tbl` 의 `5E00=^` 은 바이트 `5E 00` = U+005E, `E030=ム` 은 U+30E0.
2편의 `E4 xx` 2바이트 페이지 같은 자체 코드가 없다. U+E000~U+EFFF(사용자 영역)는 제어 코드로 쓰여 폭 재기에서 건너뛴다.
→ **한글은 U+AC00~ 그대로 쓰면 된다.** TextPet 쪽은 표에 `00AC=가` 꼴로 한글을 더한 새 표(rnr3-ko)만 있으면 된다.

## 폰트 (일본판 레드 조커 ARM9)

묘사자 표 `0x020DB860`, 항목 8바이트 `{u8 폭, u8 높이, u16 글자 수, 글자 표 주소}`:

| 묘사자 | 크기 | 글자 수 | 글자 표 | 글자 그림 | 쓰는 전역 객체 |
|---|---|---|---|---|---|
| `0x020DB860` | 12×12 | 474 | `0x020B99AC` | `0x020B14A4`~ (72바이트) | `0x020F1C28` |
| `0x020DB868` | 8×16 | 394 | `0x020C0AFC` | 64바이트 | `0x020F1C30` |
| `0x020DB870` | 8×16 굵게 | 380 | `0x020C764C` | 64바이트 | `0x020F1C38` |
| `0x020DB878` | 8×8 | 21 | `0x020C84CC` | | `0x020F1C40` |

- 글자 표 항목 8바이트: `u16 유니코드, u8 폭(나아감), u8 ?, 글자 그림 주소`. **코드 순으로 정렬**돼 있고 이진 탐색한다.
  첫 항목 `0x080040`(@, 폭 8). 12×12 폰트의 폭은 가나·한자 11, 영숫자 8~10.
- 글자 그림은 4bpp(낮은 니블이 왼쪽 점), 값은 0~3 만 쓴다. `work/font/dlg_lo.png` 로 그려 확인.
  12×12 폰트의 474자 = 기호·가나·한자 약 200·전각 영숫자. 2편 대사 16×16 폰트와 다른 새 폰트다.
- 메뉴·굵은 8×16 은 2편 그림과 같다.
- 글자 찾기 함수: `0x0200D7D0(폰트 객체, 코드)` → 항목 주소 또는 0(이진 탐색). 폭 재기 `0x0200D808`·`0x0200D878`·`0x0200D8E8` 은
  못 찾으면 `U+FF3F` 로 다시 찾는다. 다른 사본 `0x0202E250`(전역 `0x020F1C30` = 8×16 폰트 고정)은 `0x0202E0D4` 에서 부른다 —
  글자를 **VRAM 에 미리 올린 폰트의 타일 번호**로 바꿔 타일맵에 쓰는 경로(메뉴·목록 꼴).
- `0x02030A7A` 근처는 폰트 글자 전부(글자 수×0x40)를 VRAM 으로 복사한다. **8×16 폰트에 한글을 그대로 붙이면 이 화면이 VRAM 을 넘친다**
  — 2편 목록 경로처럼 동적 칸이 필요하다.
- **글자 그리기 함수는 ITCM 에 있다**(ARM9 의 자동 적재 구역 `0x01FF8000`, 0x1FE0 바이트 → `work/jp_rj/itcm.bin`).
  `0x01FF95F8(폰트 객체, 그리기 상자, 글자)`(ARM): 0 이면 끝, `\n` 이면 줄 바꿈, U+E000~U+E003 은 아이콘 칸,
  그 밖 사용자 영역은 건너뜀, 나머지는 `blx 0x0200D7D0` 으로 항목을 찾고(없으면 U+FF3F) 항목+4 의 글자 그림을 바로
  `0x01FF9798`(→ `0x01FF97B8`/`0x01FF9870`, x 가 홀수면 반 바이트 어긋난 판)로 찍은 뒤 x 에 항목+2 의 폭을 더한다.
  상자 구조: +0 아이콘 그림, +8 줄 폭, +0xA x, +0xC y, +0xE 꼴(0x40 = 고정 폭), +0x10/+0x12 한계.
  부르는 곳: `0x02011058`·`0x020132BE` 등(문자열을 u16 씩 돌며 부름), 대사 상자는 객체 `0x020F1C28`(12×12).
- 즉 **12×12 폰트를 쓰는 모든 경로가 `0x0200D7D0` 하나로 글자를 찾는다.** 이 함수에 한글 분기를 붙이면(한글이면 압축 글자를
  풀어 작은 버퍼에 놓고 가짜 항목을 돌려줌) 그리기·폭 재기가 다 따라온다. 그리기는 찾은 직후 바로 찍으므로 버퍼 하나로 된다.

### 한글을 넣는 방법 (구상)

대사(12×12): 표가 코드로 이진 탐색되므로 한글 항목을 정렬 위치(U+AC00~ 는 U+FF01 앞)에 넣고 글자 수만 바꾸면 그리기 코드는
안 고쳐도 될 수 있다. 걸림돌은 용량 — 한글 약 1,200자 × (8+72) = 약 96KB. ARM9 끝은 `0x020E5064`, 오버레이는 `0x02125BE0`~.
값이 0~3 이라 2bpp(36바이트)로 줄여 저장하고 찾기 함수에서 풀어 주는 방법, 한자 칸을 비우는 방법 등을 검토한다.
